# Polar Observatory Native Actions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Issue #66's accessible Light, Dark, and System shell plus safe native repository picking and external-link opening without changing the star-map renderer.

**Architecture:** Keep OS-bound preferences and actions behind a narrow Rust/Tauri bridge. A frontend theme controller resolves the persisted preference against `prefers-color-scheme`, while feature components consume shared primitives and CSS tokens; the existing `lib/starmap` renderer and its theme remain untouched.

**Tech Stack:** Rust 2024, Tauri 2.11.5, tauri-plugin-dialog 2.7.2, tauri-plugin-opener 2.5.4, Svelte 5.56.8, Vitest 4.1.10, phosphor-svelte 3.1.0.

## Global Constraints

- Run every command with native Windows PowerShell and native Windows executables.
- System is the first-launch theme choice; persisted choices are exactly `system`, `light`, or `dark`.
- All application-chrome colors are CSS custom-property tokens; do not edit `web/src/lib/starmap/theme.ts` or introduce theme inputs to the renderer.
- External opening accepts parsed `https` URLs only; the access token never crosses the native bridge.
- Icons are imported from the packaged `phosphor-svelte` dependency; no CDN, web font, or runtime asset fetch is allowed.
- Keep loading, empty, authentication, stale-provider, routing-error, and native-action failure states visible and recoverable.
